# Orda для Apple — iPhone, iPad, Mac

Нативное приложение на SwiftUI. Один код на три платформы, один вход, четыре
рабочих пространства (платформа, владелец, сотрудник, оператор).

## Быстрый старт

Настраивать нечего — по умолчанию сборка смотрит на прод `www.ordaops.kz`.
Для стенда поменяйте `ORDA_API_BASE_URL` в `apple/Config.xcconfig`.

```bash
open apple/Orda.xcodeproj

# или из терминала
xcodebuild -project apple/Orda.xcodeproj -scheme Orda \
  -destination 'platform=macOS' build

xcodebuild -project apple/Orda.xcodeproj -scheme Orda \
  -destination 'generic/platform=iOS Simulator' build

# тесты
cd apple/OrdaKit && swift test
```

## Приложение общается только с сайтом

Никаких ключей Supabase в сборке нет. Вход идёт через
`POST /api/auth/mobile-session`: сервер сам меняет пароль на токен, ограничивает
частоту попыток по IP и логирует неудачи. Приложение знает один адрес — сайт.

```
Приложение ──Bearer JWT──▶ /api/auth/mobile-session   вход и продление
           ──Bearer JWT──▶ /api/auth/session-role     кто я и что мне можно
           ──Bearer JWT──▶ /api/operator/*            смена, продажа, ревизия
           ──Bearer JWT──▶ /api/admin/*               бизнес-разделы
                            + x-organization-id
```

Ключ проекта Supabase не покидает сервер — раньше он попадал бы в каждую
установленную копию приложения.

## Из чего собрано

```
apple/
├── Orda.xcodeproj          проект (iOS 17+ / macOS 14+, один таргет)
├── Config.xcconfig         адреса и ключи (шаблон, без боевых значений)
├── Orda-Info.plist         Face ID, камера, проброс настроек из xcconfig
├── Contracts/
│   └── capabilities.json   снимок каталога прав — сгенерирован из веба
├── OrdaKit/                логика без UI: доступ, сеть, домен  ← тесты здесь
├── OrdaUI/                 дизайн-система: токены, движение, компоненты
└── Orda/                   приложение
    ├── App/                конфиг, корневая маршрутизация, адаптивный каркас
    ├── Auth/               Supabase Auth, Keychain, состояние сессии
    └── Features/           Platform · Business · Operator · Login
```

Папка `Orda/` подключена как синхронизируемая группа Xcode: новые файлы
подхватываются сами, править `project.pbxproj` не нужно.

## Как устроен доступ

Единственный источник правды — `GET /api/auth/session-role`. Сервер отдаёт уже
**полностью разрешённый** набор прав: он успел применить базовый набор роли,
снятия в `role_capabilities` и `org_role_capabilities`, персональные оверрайды
и рубильник организации. Приложение эти слои не пересчитывает.

Клиенту остаются два гейта поверх:

| Гейт | Откуда | Что делает |
|---|---|---|
| Модули организации | `orgFeatures` | прячет раздел, который организация не оплатила |
| Выключенные маршруты | `rolePermissionOverrides` | точечный запрет пути владельцем |

Всё это в `OrdaKit/Access/AccessResolver.swift`, покрыто 23 тестами — по
сценарию на каждую роль, включая «рубильник режет даже владельца» и
«неоплаченный модуль прячет раздел при наличии прав».

**Скрытая кнопка — не защита.** Настоящая проверка на сервере; приложение
обязано корректно показывать 403 (`APIError.forbidden` знает, какого права не
хватает, и говорит это по-русски).

## Каталог прав генерируется, а не пишется руками

397 прав живут в `lib/core/capabilities.ts`. Дублировать их в Swift означало бы
гарантированное расхождение.

```bash
npm run capabilities:export   # обновить Swift-зеркало из TypeScript
npm run capabilities:check    # упасть, если разошлось (стоит в verify:release)
```

Генератор — `scripts/export-capabilities.mjs`. Файлы в
`OrdaKit/Sources/OrdaKit/Access/Generated/` править нельзя, они перезаписываются.

## Три платформы

Раскладку выбирает `AdaptiveWorkspace` по `horizontalSizeClass`:

| | iPhone | iPad | Mac |
|---|---|---|---|
| Каркас | таб-бар, 4 раздела + «Ещё» | `NavigationSplitView`, 2 колонки | `NavigationSplitView` + меню-бар |
| Списки | `List` | `List` → далее `Table` | `Table`, контекстные меню |
| Клавиатура | — | внешняя | ⌘R и остальные команды |

Экраны общие, поэтому Mac-версия не может незаметно отстать от iPhone.

## Что уже работает

**Основа**
- Вход по почте (сотрудник) или логину (оператор — почту достраивает сервер)
- Сессия в Keychain, обновление токена с защитой от параллельных refresh
- Маршрутизация по роли: платформа / бизнес / оператор
- Навигация бизнес-пространства **выводится из реальных прав**
- Адаптивный каркас на трёх платформах, меню-бар и ⌘R на Mac

**Оператор — рабочий контур целиком**
- Смена: открытие со стартом кассы, живые итоги, закрытие со сверкой
- Обязательные чек-листы видны заранее, а не в момент отказа при закрытии
- Продажа: непрерывный сканер камеры, каталог витрины, корзина, оплата
- Чек уходит клиенту ссылкой через `ShareLink` — печатать нечего
- **Офлайн-очередь**: нет связи → чек ложится на диск и уходит позже
- Ревизия: назначенные акты, слепой счёт, скан += 1, прогресс по секции

## Офлайн-продажи

Точка может быть в подвале, а очередь у кассы ждать не будет. Чек сначала
пробует уйти сразу; при сетевой ошибке ложится в файл на устройстве и
отправляется при первой возможности.

Повторы безопасны: каждый чек несёт `local_ref`, и сервер по нему
дедуплицирует (`app/api/operator/inventory-sales`). «Отправили, но не дождались
ответа» не превращается во второй чек.

Смена не закроется, пока очередь не пуста: её суммы ещё не попали в итоги, и
касса не сошлась бы.

## Push

Сервер умеет оба канала: Expo (React Native приложение) и APNs (это
приложение). Разделение — по форме токена в `lib/server/push.ts`.

Для APNs нужны переменные окружения:

```
APNS_KEY_ID, APNS_TEAM_ID, APNS_PRIVATE_KEY, APNS_BUNDLE_ID
APNS_ENVIRONMENT=production|sandbox
```

`APNS_BUNDLE_ID` должен совпадать с `PRODUCT_BUNDLE_IDENTIFIER` из
`Config.xcconfig`.
