# Orda Control — режиссура промо

Дом-стайл кампании: визуальная система, словарь движений, звук, приёмка.
Действует для всех роликов — горизонтального, hero-cut и вертикалей.

Это документ про **как**. Про **что** — `СЦЕНАРИЙ.md`. Про **почему именно
так** — `РАЗБОР-СЦЕНАРИЯ.md`.

---

## 1. Чем должен ощущаться Orda

> Операционная система бизнеса. Не ещё одна кассовая программа.

Ассоциации, которые держим в голове при каждом решении: контроль, точность,
система, единый источник данных, спокойствие владельца.

Ориентир по уровню исполнения — продуктовые фильмы Apple, Linear, Stripe,
Raycast, Vercel. **Не копировать.** Оттуда берём не приёмы, а планку: движение
уверенное и объясняющее, а не игровое и декоративное.

Цель, сформулированная от противного: зритель не должен подумать «это сделал
ИИ». Он должен подумать «это делала небольшая сильная моушн-студия».

## 2. Визуальная система

Всё взято из продукта, ничего не придумано.

### Светлый мир — портал, касса, лендинг

| Роль | Значение |
|---|---|
| Фон | `#ffffff`, поверхность `#f7f9fc`, панель `#eef2f8` |
| Текст | `#0f2038`, вторичный `#56657d`, подписи `#64748b` |
| Границы | `#e2e8f0`, плотная `#d6dde8` |
| Акцент | `#16a34a`, для текста `#15803d`, на плашках `#126b33` |
| Тёмная врезка | `#0f2038` с точечной сеткой `rgba(255,255,255,0.07)` 24px |

### Тёмный мир — мобильное приложение, киоск

| Роль | Значение |
|---|---|
| Фон | `#070809`, поверхность `#0d1014`, карта `#12161b` |
| Текст | `#ffffff`, вторичный `#b6c0cd`, приглушённый `#8b95a4` |
| Границы | `#222831`, мягкая `#191e25` |
| Бренд | `#10b981`, яркий `#3df0b6`, подложка `#0b3b2e` |
| Акценты состояний | `#22d3ee` Kaspi · `#fbbf24` внимание · `#fb7185` тревога |

**Контраст миров — приём, а не случайность.** Переход со светлого десктопа на
тёмный телефон читается как смена роли. Не смешивать их в одном кадре, кроме
финальной сборки экосистемы.

### Типографика

| Роль | Шрифт | Размеры |
|---|---|---|
| Доминанта кадра | Manrope 800, tracking −0.03em | 64–108px (16:9) · 56–88px (9:16) |
| Доказательство | Inter 500/600 | 24–36px · 32–44px |
| Подписи интерфейса | Inter 600, uppercase, tracking 0.06–0.16em | 17–20px |

Локальные `woff2` с кириллицей, латиницей и latin-ext. **Без latin-ext символ ₸
выпадает в тофу** — проверять на каждом новом шрифте.

### Контраст — жёсткий гейт

`hyperframes check` проверяет WCAG AA и не пропускает провал. Заранее известное:

- `#16a34a` на белом — 3,28:1. Для обычного текста **нельзя**, только от 24px.
- `#15803d` на белом — 5,02:1. Норма.
- `#22c55e` на белом — 2,28:1. Для текста **нельзя вообще**, только заливка.
- `#94a3b8` на белом — 2,56:1. Для текста **нельзя**, брать `#64748b`.

## 3. Иерархия кадра

В каждом кадре ровно одна доминанта.

| Уровень | Что | Как выглядит |
|---|---|---|
| **PRIMARY** | одна мысль кадра | дисплейный кегль, полный контраст, в центре внимания |
| **SECONDARY** | доказательство мысли | вдвое мельче, приглушённый цвет |
| **DECORATIVE** | лейблы интерфейса, подписи осей | мелко, до 60% прозрачности, читать не обязательно |

**Проверка:** закрой всё, кроме PRIMARY. Кадр понятен? Если нет — доминанта
выбрана неверно.

Текст держится на экране: короткий лейбл — от 0,8с в устоявшемся виде,
предложение — 0,3с на слово. Быстро появился и завис — можно. Быстро появился и
исчез — нет.

## 4. Словарь движений

Движение обязано объяснять одно из: иерархию, причину и следствие, смену
состояния, перемещение данных, переход между рабочими местами, смену роли.

Движение, которое ничего из этого не объясняет, вырезается.

### Что используем

- **match cut** — объект продолжается в следующей сцене, изменившись
- **masked reveal** — раскрытие по маске вместо появления по прозрачности
- **spatial continuity** — сцена вытекает из предыдущей, а не сменяет её
- **object permanence** — сквозной объект живёт через весь фильм
- **pull-out** — камера отъезжает, и деталь оказывается частью большего
- **FLIP** — элемент переезжает между двумя раскладками
- **number morph** — от вчерашнего значения к сегодняшнему
- **progressive disclosure** — информация раскрывается по мере надобности
- **UI state transition** — интерфейс отвечает на действие
- **controlled blur** — расфокус как смена внимания, не как украшение

### Чего не делаем

- бесконечные fade-in как основной язык
- одинаковый spring на всё подряд
- случайно плавающие карточки
- zoom без причины
- частицы, блобы-градиенты, фальшивое 3D
- glassmorphism сверх меры
- постоянные whoosh
- одинаковое появление всех элементов подряд
- текст, который не успеть прочитать
- три интерфейса одновременно в кадре

### Камера

Разрешены: push in, pull out, pan, track, имитация rack-focus, сдвиг
перспективы, макро-план интерфейса, широкий план экосистемы.

**Камера всегда медленнее внутренних анимаций интерфейса.** Тряски нет.

### Паспорт кадра

Для каждой значимой сцены прописывается:

```
purpose      — что зритель должен понять
composition  — где что стоит
entrance     — как входит
hold         — сколько держится в покое
interaction  — что происходит внутри
exit         — как уходит
transition   — чем сцена сцеплена со следующей и почему именно этим
camera       — движение камеры, если есть
easing       — характер движения
sound cue    — звуковой акцент, если нужен
```

Поле `transition` без ответа на «почему именно этим» считается незаполненным.

## 5. Числа

Числа в этом продукте — главный герой. Анимировать их осмысленно.

- Есть вчерашнее значение → **морфим**: `382 100 → 412 800`
- Ноль осмыслен → **считаем от нуля**: очередь офлайн `0 → 12 → 0`
- Число уже известно зрителю → **не анимируем вообще**, оно просто есть
- Разряды — неразрывным пробелом: `412 800 ₸`
- Моноширинные цифры (`tabular-nums`), иначе число дёргается при счёте

## 6. Звук

Проектируется после моушн-сториборда и до финального рендера.

| Категория | Когда |
|---|---|
| BGM | всегда, 0.26–0.30, без буста |
| сканер | на каждый товар в корзину |
| UI click | появление узла схемы, переключение вкладки |
| soft impact | приземление логотипа |
| success cue | итог смены, подтверждённая синхронизация |
| network failure | падение сети — единственный драматический звук |
| sync cue | возврат сети |
| brand sting | финальный адрес |

**Звук не на каждое движение.** Акцент ставится там, где он помогает понять
событие. В 85-секундном фильме звуковых акцентов не больше пятнадцати.

Музыка задаёт ритм, но не обязывает попадать каждым движением в каждую долю:
сильные доли — смены сцен, слабые — акценты интерфейса, брейк — драматическое
событие, подъём — раскрытие продукта, финальный удар — бренд.

Один приём на фильм: при падении сети музыка приглушается до 0.12 на полторы
секунды и возвращается на синхронизации. Больше ducking нигде.

## 7. Интерфейс в кадре

Приоритет источника:

```
реальный интерфейс
  → реальный интерфейс + моушн-оверлеи
    → реконструкция вёрсткой
      → абстрактная иллюстрация
```

Придумывать экран, который можно получить с рабочего стенда, — нельзя.

Реконструкция допустима, когда нужна идеальная композиция, контролируемая
анимация, состояние, которое тяжело записать (падение сети), или безопасные
демо-данные.

Микровзаимодействия, без которых продукт выглядит мёртвым: курсор, скан
штрихкода, печать чека, касание пальцем, раскрытие карточки, фокус на графике,
смена вкладки, уведомление, состояние синхронизации, загрузка, галка.

## 8. Демо-данные

В кадре нет ни одного настоящего: названия компании, имени сотрудника,
телефона, суммы, клиента, складского остатка, финансового показателя.

Используются согласованные демо-данные из `СЦЕНАРИЙ.md`, раздел 3. Все
связанные цифры сходятся между собой — если зритель начнёт складывать, сойдётся.

Новая цифра сначала попадает в сценарий, потом в кадр. Не наоборот.

## 9. Заявления

Показываем, что делает Orda. Не утверждаем, чего не умеют другие.

Запрещено без проведённого исследования:

- «единственный в Казахстане»
- «нет ни у одного конкурента»
- «лучше, чем X»
- проценты роста, которых мы не измеряли («+30% к выручке»)

Разрешено: описание того, что система делает, и цифры из демо-данных, честно
обозначенные как демонстрационные.

## 10. Форматы

| Версия | Размер | Длина | Назначение |
|---|---|---|---|
| Product film | 1920×1080 | 85с | сайт, презентация, встреча |
| Hero cut | 1920×1080 | 30с | реклама, шапка сайта |
| Вертикали ×3 | 1080×1920 | 15с | Shorts, Reels, TikTok |

Вертикаль **не кроп**. Пересборка: заголовок выше, продукт ближе и крупнее,
текста меньше, объект в центральной зоне, нижние 15% пустые под интерфейс
плеера. Минимальный кегль в вертикали — 44px.

Всё в 30 fps.

## 11. Приёмка

Два прохода. Первый рендер финальным не считается никогда.

**Проход 1 — структура.** Сюжет, порядок сцен, понятность, длительность, смысл
каждого кадра.

**Проход 2 — полировка.** Характер движения, тайминги, переходы, типографика,
звук, микровзаимодействия, камера, визуальная цельность.

### Чек-лист по каждой сцене

Смотреть глазами готовое видео, а не код.

```
Понятно за одну секунду?
Текст успеваю прочитать?
Главное — очевидно?
Движение помогает или отвлекает?
Не слишком ли много одновременно?
Переход выглядит намеренным?
Сцена из того же фильма, что и соседние?
Интерфейс не искажён пропорциями?
Русская типографика в порядке — переносы, кавычки, тире, ₸?
Есть мёртвые кадры, где ничего не происходит?
Случайные наложения?
Безопасные зоны соблюдены?
```

По итогам — вердикт по каждой сцене: `ОСТАВИТЬ` · `ПОЧИНИТЬ` · `УБРАТЬ` ·
`УПРОСТИТЬ` · `ПЕРЕТАЙМИТЬ`. И только после этого финальный рендер.

## 12. Как это собирается технически

Движок один — Hyperframes. Второго моушн-движка в проекте нет и не будет:
смешивать их без причины дороже, чем любая выгода.

Маршрут: `/hyperframes` (точка входа) → `/product-launch-video` (воркфлоу) →
доменные навыки `hyperframes-core` (контракт композиции), `-animation`
(движение), `-keyframes` (камера и seek-safe кадры), `-creative` (дизайн-спека),
`-audio` (микс), `-registry` (готовые блоки), `media-use` (медиа), `-cli`
(проверка и рендер).

Этот документ — вход в их работу: дом-стайл, который они обязаны соблюдать.

Гейт перед рендером один: `npx hyperframes check` — ноль ошибок по линту,
рантайму, вёрстке, движению и контрасту.
