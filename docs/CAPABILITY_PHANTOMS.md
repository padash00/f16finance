# Разбор прав без проверки

51 право из каталога не спрашивает никто — ни сервер, ни интерфейс. Ниже разбор
каждого: что это на самом деле и что с ним делать. Проверял по двум признакам —
есть ли страница раздела и есть ли маршрут, — и дальше смотрел код.

Итог: **выбросить 21**, **сделать 18**, **проверить гейт 12**.

## Выбросить — права, которых не должно быть

| Право | Почему |
|---|---|
| `pos.sell`, `pos.refund`, `pos.discount` | Страницы `/pos` нет и не будет: касса живёт в программе за стойкой и в киоске, а они ходят по токену устройства — каталог прав там не действует вовсе. |
| `debug.run_tests` | Раздел разработчика. Право на кнопку, которой у клиента нет. |
| `structure.drag_drop_reorder` | Это жест, а не действие. Сохранение порядка идёт под правом изменения структуры; отдельное право на способ перетаскивания ничего не защищает. |
| `dashboard.dismiss_warning` | Скрытие карточки живёт в интерфейсе и на сервер не уходит. Право без последствий. |
| `welcome.view`, `workspace.view` | Служебные экраны: их видит любой вошедший, иначе войти было бы некуда. |
| `store-receipts.apply_template`, `delete_template`, `bulk_markup`, `bulk_sale_price`, `quick_add_barcode` | Всё это правки формы приёмки в браузере. На сервер уходит одна готовая приёмка под правом `store-receipts.create`. Отдельные права защищают шаги мастера, а не данные. |
| `store-writeoffs.apply_template`, `save_template`, `quick_add_barcode` | То же самое у списания. |
| `store-revisions.add_item_barcode` | Способ добавить строку в акт. Сам акт закрыт правами ревизии. |
| `store-requests.edit` | Количество правится до отправки заявки, в форме. Отправка идёт под правом создания. |
| `incidents.close` | Действие есть, но под правом `incidents.update` — им закрывают, подтверждают и оспаривают. Второе право на тот же маршрут только путает. |

## Сделать — действие нужно, но его нет

Здесь право обещает то, чего в системе нет вообще. Либо делать, либо убирать —
но решать это по одному, с владельцем.

| Право | Что означает сделать |
|---|---|
| `shifts-reports.reopen` | Переоткрыть закрытую смену. Маршрута нет: ошибку в закрытой смене сейчас исправить нечем. |
| `salary.add_extra_day` | Доп. рабочий день в ведомость — вышел в выходной, надо оплатить. |
| `tasks.bulk_delete` | Массовое удаление задач: сейчас только по одной. |
| `knowledge-admin.publish` | Публикация статьи. Сейчас статья создаётся и правится, но состояние «опубликована» никто не переключает через право. |
| `knowledge-admin.run_checklist`, `skip_checklist` | Запустить чек-лист в смену вручную и пропустить обязательный. Оба — про исключения, которые сейчас решаются устно. |
| `stations.edit_theme`, `stations.edit_kiosk_announcement` | Оформление киоска и объявление на станции. |
| `pass.view` | Пропуска. Раздел заявлен, маршрута нет. |
| `store-requests-journal.view` | История заявок отдельным журналом. |
| `operator-achievements.view`, `operator-tasks.view`, `operator-lead.view` | Разделы операторского контура: страницы есть, серверных маршрутов под этими именами нет — доступ считается по другим правам. |
| `pos-returns.view` | Возвраты кассы. |
| `ratings.view` | Рейтинги. |
| `shifts-reports.export`, `analytics.export`, `analysis.export`, `store.export`, `shifts.export` | Выгрузки. Делает их браузер из уже загруженных данных, поэтому право ничего не решает: кто видит цифры, тот их и выгрузит. Либо переносить выгрузку на сервер и там проверять право, либо убрать. |

## Проверить гейт — право есть, но проверка идёт иначе

Права на просмотр разделов, где страница существует, а маршрут не спрашивает
именно это право. Здесь важно не то, что право «висит», а то, чем закрыт раздел
на самом деле.

`news.view`, `messages.view`, `team-chat.view`, `team-analysis.view`,
`ai-cfo.view`, `expense-analysis.view`, `settings.view`, `sales-kpi.export`,
`profitability.simulate`, `telegram.toggle_connection`, `telegram.test_webhook`,
`point-devices.manage_feature_flags`.

Проверенное:

- **`sales-kpi.export`** — маршрут `/api/admin/sales-kpi/export` требует вход,
  но право не спрашивает. Это настоящий замок на картинке: кнопку человек не
  увидит, а запрос сервер примет.
- **`incidents.close`** — закрывает `incidents.update`, см. выше.

Остальные из этого списка нужно пройти так же: открыть маршрут и посмотреть, что
он требует. Пока это не сделано, считать раздел закрытым нельзя.

## Как пользоваться

`npm run audit:capabilities` печатает актуальный список. Строка исчезает оттуда
двумя способами: право реализовали или право убрали. Оба хороши, третьего
(«оставим, разберёмся потом») быть не должно — именно так и появились эти 51.
