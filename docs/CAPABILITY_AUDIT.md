# Права без проверки

`npm run audit:capabilities` сверяет каталог прав с тем, кто их вообще
спрашивает: сервер (`requireCapability` и родня) или только интерфейс.

Зачем: каталог прав — обещание. Если право есть, владелец видит его в настройках
доступа и вправе ожидать, что выключение что-то меняет. Право, которого никто не
проверяет, — обещание невыполненное, а ещё повод неделю искать «недостающую
кнопку» там, где её никогда не было.

## Что уже разобрано

| Право | Что оказалось |
|---|---|
| `store-movements.create` | Фантом. Маршрута нет, а перемещение со склада на витрину давно работает под `store-showcase.move`: заявка наверх, возврат вниз сразу. Право надо убрать из каталога. |
| `access.generate_password` | Ложная тревога. Сервер закрывает жёстче каталога — `/api/admin/set-password` пускает только суперадмина. |

## Как читать отчёт

**Фантом** — право не упоминается ни на сервере, ни в интерфейсе. Либо действие
не сделано, либо право лишнее.

**Только в интерфейсе** — три возможных случая, и различить их может только
человек:

1. сервер закрывает жёстче (суперадмин, роль владельца) — всё в порядке;
2. действие идёт через маршрут с другим правом — право в каталоге лишнее;
3. сервер не проверяет ничего — замок на картинке: кнопку человек не увидит, а
   запрос сервер примет.

Третий случай — настоящая дыра, и разбирать список стоит с прав, за которыми
стоят деньги и доступ: `*.export`, `*.reveal_*`, `*.reset_*`, `pos.*`.

## Почему проверка ничего не роняет

Список — повод разобраться, а не запрет выпускать релиз: половина строк
объясняется чужим правом или более строгой проверкой. Гейт из этого получится,
когда список разберут до нуля.
