## Часть 1. Сайт — что нашлось

### 1.1. Ограничитель попыток входа не работает на проде — **важно**

`lib/server/rate-limit.ts` хранит счётчики в `Map` в памяти процесса. Комментарий в самом файле честно говорит: *«Resets on server restart — suitable for edge cases, not production-grade»*.

На Vercel каждый серверлесс-инстанс имеет **свою** память. При нескольких инстансах лимит «10 попыток за 5 минут» превращается в «10 попыток на инстанс», а холодный старт обнуляет счётчик полностью.

Это касается и нового `/api/auth/mobile-session`, который я добавил: он опирается на этот же лимитер. Формально защита есть, фактически подбор пароля ей не остановить.

**Что делать:** перенести счётчики в Vercel KV или Upstash Redis. Изменение точечное — интерфейс `checkRateLimit()` остаётся тем же, меняется только хранилище.

### 1.2. `/api/health` отдаёт 404

Есть `/api/health/supabase` и `/api/health/whoami`, но самого `/api/health` нет. Если этот адрес прописан во внешнем мониторинге, он всё время видит падение.

**Что делать:** добавить корневой роут, агрегирующий проверки, либо поправить адрес в мониторинге.

### 1.3. Тесты не участвуют в проверке релиза

```
verify:release = typecheck && capabilities:check && lint && build
```

`npm test` (40 тестов, включая расчёт зарплаты) в цепочку не входит. Логика начисления зарплаты может сломаться, и релиз всё равно пройдёт.

**Что делать:** добавить `npm test` в `verify:release`.

### 1.4. 411 предупреждений линта

Ошибок нет, но предупреждения копятся и создают шум, в котором тонет новое. Основные типы: неиспользуемые импорты (сотни), `react-hooks/exhaustive-deps`, `<img>` вместо `next/image`.

Опасны из них немногие: `exhaustive-deps` на страницах с `useMemo`, где пропущенная зависимость даёт устаревшие данные на экране. Остальное — гигиена.

**Что делать:** прогнать `eslint --fix` (снимет ~11 автоматически), затем разобрать `exhaustive-deps` вручную. Массово подавлять не стоит — среди них есть настоящие.

### 1.5. Expo-приложение остаётся в репозитории

71 файл в `mobile/`. Оно рабочее и обслуживает Android, но теперь дублирует нативное: два клиента к одному API, два места, где надо помнить про новое право или поле.

**Что делать:** решить явно — либо Expo остаётся Android-клиентом и его поддерживают, либо он замораживается. Худший вариант — оставить как есть и обнаружить расхождение через полгода.

### 1.6. Нет машинного контракта API

342 роута, ни одной схемы. Каталог прав я вывел в контракт (`apple/Contracts/capabilities.json` + генератор), но формы ответов по-прежнему приходится читать глазами и переносить в Swift руками — это источник расхождений.

**Что делать:** описать хотя бы операторский и дашбордный контуры через `zod` (он уже в зависимостях) и генерировать из него и типы, и Swift-DTO.

## Часть 2. Приложение — чего не хватает

### 2.1. Покрытие API

**Операторский контур — 14 из 23.** Не подключены:
`checklist/templates` (используется агрегат `knowledge`), `arena` (игровые станции), `customers` (клиенты и лояльность), `lead` (моя точка для старших), `point-qr-confirm`, `shift/report`, `shift/handover` (метод есть в сервисе, экрана нет), `knowledge/confirm` подключён.

**Админский контур — 7 из 173.** Подключены: дашборд, компании, очередь расходов, одобрение, отклонение, доходы, расходы. Не подключено практически всё остальное: склад, зарплата, операторы, смены, отчёты, налоги, аналитика, POS, клиенты, настройки.

### 2.2. Экраны каталога прав — каркас, не данные

Все 82 страницы открываются, показывают доступные пользователю действия и помечены плашкой «экран данных подключается на следующем этапе». Это честно, но это не работающие экраны.

**Приоритет по ценности** (мой порядок, если делать дальше):

1. **Склад** — остатки, заявки, приёмка, ревизия. Самый большой вес в ежедневной работе.
2. **Команда** — зарплата, операторы, смены, кадры.
3. **Отчёты и аналитика** — недельный отчёт, ОПиУ, прогноз.
4. **Операционка** — задачи, инциденты, чек-листы админской стороны.
5. **Система** — доступы, настройки, логи. Реже нужны с телефона.

### 2.3. Push-уведомления не подключены со стороны приложения — **пробел**

На сервере APNs реализован (`lib/server/apns.ts`), эндпоинт регистрации токена принимает нативные токены. Но **приложение никогда не запрашивает разрешение и не отправляет токен**. То есть канал готов, а отправлять некуда.

Это самая дешёвая крупная фича из оставшихся: ~полдня работы, и владелец начнёт получать «оператор подал расход» в реальном времени.

### 2.5. Иконка приложения отсутствует

`Assets.xcassets/AppIcon.appiconset` содержит только описание слотов, самих изображений нет. На домашнем экране приложение будет серым квадратом.

Фирменный знак уже нарисован кодом (`OrdaMark` — шестиугольник из трёх граней куба, используется в заставке). Из него нужно отрендерить PNG 1024×1024 и нарезать по слотам.

### 2.6. Офлайн работает только для продаж

Очередь на диске есть у чеков. Всё остальное — ревизия, чек-листы, задачи — при потере связи просто показывает ошибку. Для ревизии это особенно обидно: она идёт часами, и потерять час подсчётов из-за подвала неприятно.

**Что делать:** распространить механизм очереди на подсчёты ревизии и ответы чек-листов.

### 2.7. Кэш не переживает перезапуск

Данные живут в памяти хранилищ. При каждом запуске приложение показывает скелетоны и ждёт сеть, хотя вчерашняя выручка уже была загружена. В плане на это заложен SwiftData — не сделано.

## Часть 4. Что уже сделано хорошо

Чтобы картина была честной в обе стороны.

- **Каталог прав не может разойтись.** 397 прав генерируются из TypeScript в Swift, `capabilities:check` в `verify:release` падает при расхождении.
- **Права считаются правильно.** 36 тестов, включая неочевидное: рубильник организации режет право даже у владельца; неоплаченный модуль прячет раздел при наличии права; просмотр требует именно `.view`.
- **Продажи не теряются.** Очередь на диске плюс дедупликация по `local_ref` на сервере — обрыв связи после отправки не создаёт второй чек.
- **Палитра графиков проверена машиной, а не глазом.** Первый вариант провалил проверку (янтарь и розовый не различались даже нормальным зрением), заменён.
- **Токены в Keychain**, а не в открытом файле, как было в Expo-версии.
