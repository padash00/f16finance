# Уведомления на iPhone: настройка ключа APNs

Код отправки в приложении и на сервере готов: задача, личное сообщение и
упоминание в чате уже вызывают отправку. Пока не заданы переменные ниже,
`lib/server/apns.ts` молча ничего не делает — по замыслу, чтобы разработка не
падала без ключей. Снаружи это выглядит как «уведомления не приходят».

Проверить, в чём дело, можно из приложения: **Профиль → Проверить уведомления**.
Она честно отвечает, что именно не так — нет устройств, нет ключа, устаревшие
токены или всё в порядке.

## 1. Завести ключ (один раз, 3 минуты)

1. <https://developer.apple.com/account/resources/authkeys/list> → **+**.
2. Имя: `Orda Push`. Отметить **Apple Push Notifications service (APNs)**.
3. Continue → Register → **Download**. Файл `AuthKey_XXXXXXXXXX.p8` скачивается
   **один раз** — второй возможности не будет, сохраните его.

Ключ общий для всей команды разработчика: заводить отдельный на каждое
приложение не нужно.

## 2. Получить значения переменных

```
node scripts/apns-env.mjs ~/Downloads/AuthKey_XXXXXXXXXX.p8
```

Скрипт печатает готовые строки. Ключ отдаётся в base64 одной строкой намеренно:
PEM с переносами при вставке в поле переменной ломается, и APNs отвечает
`invalid key`.

## 3. Вставить в Vercel

Settings → Environment Variables, окружение **Production**:

| Переменная | Значение |
|---|---|
| `APNS_KEY_ID` | 10 символов из имени файла ключа |
| `APNS_TEAM_ID` | `YRA24D32N2` |
| `APNS_PRIVATE_KEY` | base64 из скрипта |
| `APNS_BUNDLE_ID` | `kz.ordaops.apple` |
| `APNS_ENVIRONMENT` | `production` |

После сохранения нужен **новый деплой**: переменные подхватываются при сборке.

## 4. Проверить

В приложении: **Профиль → Проверить уведомления**. Ожидаемый ответ —
«Отправлено на N устройств», и следом баннер на экране.

Если пишет «устройств не зарегистрировано» — человек не разрешил уведомления
или не входил после установки: регистрация происходит после входа.

## Про sandbox и production

`APNS_ENVIRONMENT` должен совпадать с `APS_ENVIRONMENT` сборки:

| Откуда сборка | APS_ENVIRONMENT | APNS_ENVIRONMENT |
|---|---|---|
| App Store, TestFlight | `production` (Release) | `production` |
| Запуск с Mac на устройство | `development` (Debug) | `sandbox` |

Несовпадение — самая частая причина тишины при верных ключах: боевой токен,
отправленный на отладочный APNs, отклоняется без объяснений. Прод-сервер должен
стоять на `production`; отлаживать пуши на сборке с Mac нужно на стенде.

Симулятор push от Apple не получает вовсе — только устройство.
