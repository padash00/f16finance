# Сброс пароля с телефона

Сотрудник меняет пароль не выходя из приложения: **Вход → «Не получается войти» → «Сменить пароль»**.

Два шага: рабочая почта → код из письма и новый пароль.

## Что нужно один раз настроить

Код в письмо добавляет Supabase, и по умолчанию его там нет — в стандартном
шаблоне только ссылка на сайт.

1. Supabase Dashboard → **Authentication → Emails → Reset Password**.
2. Добавить в тело письма строку с кодом:

   ```html
   <p>Код для смены пароля: <b>{{ .Token }}</b></p>
   <p>Код действует несколько минут и подходит только один раз.</p>
   ```

3. Ссылку `{{ .ConfirmationURL }}` из шаблона **не убирать**: она остаётся
   запасным путём для тех, кто меняет пароль на сайте.

Пока `{{ .Token }}` в шаблоне нет, приложение отправит письмо, но вводить будет
нечего — человек увидит только ссылку. Поэтому на втором шаге написано прямо:
«если в письме только ссылка — откройте её».

## Как устроено

| Шаг | Кто делает | Что происходит |
|-----|-----------|----------------|
| Запрос кода | `POST /api/auth/password-reset` `{action:"request"}` | сайт зовёт GoTrue `/recover`, письмо уходит |
| Смена пароля | `POST /api/auth/password-reset` `{action:"confirm"}` | код меняется на сессию (`/verify`), ею ставится пароль (`PUT /user`), сессия гасится |

Ключ проекта не уезжает в сборку: приложение знает только адрес сайта — так же,
как при входе (`/api/auth/mobile-session`).

**Существование почты наружу не подтверждается.** Ответ на запрос кода
одинаковый для заведённой и незаведённой почты — иначе форма превращается в
способ узнать, кто работает в компании.

Ограничения по IP: 5 писем и 10 попыток кода за 15 минут. Срок жизни кода и
число попыток проверяет сам GoTrue — свой счётчик был бы второй правдой.

## Операторы

Оператору это не подходит: он входит по логину, а не по почте, и пароль ему
выдаёт владелец. В подсказке входа так и написано — сбросить самому нельзя,
нужно попросить новый.
